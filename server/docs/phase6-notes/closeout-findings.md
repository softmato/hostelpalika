# Phase 6 closeout findings (to fold into review_fixes_needed.md)
- BKP-1: setBackupKey on TS read a non-base64 key with the lenient fromBase64; Go ports the same reader (`crypto.FromBase64`), no behaviour change. The restore insert count on a partial unique-index refusal is computed from BulkWriteException write errors in Go.
- FIN-6: waiveLateFine crashed (500) on an invoice row with no `lines` field (lean skips defaults). Go treats it as no lines; TS fixed with `(invoice.lines ?? [])`.
- FIN-7: createFeeSchedule deleted or closed the open rate card before inserting its successor, and deleteFeeSchedule deleted before reopening the predecessor; a failure between them left the hostel with no open card. Go runs each pair in one transaction. TS owed: wrap both in `session.withTransaction`.
- FIN-8: listAllRoomTypes / listAvailableRoomTypes sorted on `roomType.localeCompare`, so one room configuration without a name 500'd the rate card screen. Fixed in TS and Go (`roomType ?? ""`).
- FIN-9 (open, TS + Go owed): a billing run with a month discount already set bills the rent line at the discounted amount with no `concessionPercent` marker. A later edit of that discount runs the backfill on the discounted figure, so the discount stacks (50% then 40% gives 3,000 of 10,000, not 6,000), and the backfill's base also takes KHATA and FINE lines. Fix in both: the run writes the full rent line plus the marked CREDIT line the backfill writes, and the backfill's base counts only SCHEDULE/OVERRIDE/MANUAL lines.
- R28 (billing): runBillingCycle wrote the invoice, the khata mark and the credit line in three steps. Go runs the three per resident in one transaction. TS owed: `session.withTransaction` around the three.
- FIN-10: saveGatewayConfig wrote the slot with arrayFilters, which threw (500) on a profile with no `gateways` array, and an unchanged save (modifiedCount 0) fell through to a push+upsert that hit the unique hostelId. Fixed in TS and Go: positional `$` update matched on the slot, push only when no slot matched.
